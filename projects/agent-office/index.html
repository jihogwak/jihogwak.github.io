Agent Office

역할이 다른 에이전트가 논문 수집·선별·분석·검토·정리를 순서대로 수행하고, 조사 결과와 인용 관계를 쌓아가는 연구 지원 도구입니다.

형태
역할별 에이전트로 구성한 가상 사무실
주요 기술
FastAPI · SQLite · Canvas · Docker
처리 흐름
수집 → 선별 → 분석 → 검토 → 정리

01 / 프로젝트 소개

연구 에이전트들이 일하는 사무실

Agent Office는 에이전트의 역할과 작업 상태를 사무실 화면에서 확인하는 웹 도구입니다. 논문 검색과 결과 정리뿐 아니라, 각 단계의 입력·출력과 실행 이력을 함께 볼 수 있게 구성했습니다.

02 / 배경과 목적

논문 조사를 하나의 실행 흐름으로 연결하기

논문 수집, 선호도 선별, 방법론 분석, 한계점 검토, 최종 정리를 다섯 역할로 나눴습니다. 앞 단계의 결과를 다음 단계에 전달해, 각 에이전트가 같은 주제를 반복 검색하는 대신 하나의 조사 흐름을 이어가도록 했습니다.

03 / 구현한 것

검색부터 보고서까지, 단계별 입력과 출력

arXiv에서 제목·초록·메타데이터를 수집하고 검색어 관련도와 저장된 선호도로 후보를 선별합니다. 이후 방법론 분석과 한계점 검토, 최종 정리를 진행하며 역할별 상태와 결과를 DB에 저장합니다. 논문 분석의 기본 범위는 초록과 메타데이터입니다.

04 / 문제 해결 과정

관련 없는 논문을 억지로 채우지 않기

검색어 관련도가 0점인 논문도 추천 편수를 채우기 위해 통과하던 문제를 수정했습니다. 검색 조건과 제목·초록의 근거를 먼저 확인한 뒤 선호도로 정렬하고, 조건을 통과한 논문이 없으면 0편을 허용하도록 바꿨습니다.

05 / 결과물

반복 조사가 관심 분야 지도로 이어지도록

선별된 논문의 참고문헌과 후속 인용을 별도 수집해 관심 지도에 누적합니다. 같은 논문과 인용 관계는 병합하고, OpenAlex와 arXiv 원문에서 확인한 출처를 남깁니다. 조사 주제 연결과 실제 인용 관계도 구분해 표시합니다.

06 / 배운 점

자동화의 결과를 확인할 수 있어야 합니다.

작업이 완료됐다는 표시만으로는 조사 품질을 판단하기 어렵습니다. 단계별 입력·출력, 검색 근거와 제외 이유, 인용 출처를 확인할 수 있게 만드는 일이 중요했습니다. 인용 0건과 미색인·요청 실패도 구분해 기록했습니다.

07 / 실행과 운영

반복 실행과 실패 이후의 상태까지 다루기

예약 실행, 대기열, 취소와 재시작 이후의 복구 상태를 관리합니다. 실행 중인 역할은 사무실 화면에 반영하고, 보고서와 인용 정보는 지속 저장합니다. 외부 LLM 분석은 키가 설정된 경우에 실행하며, PDF 본문 분석과 실제 임베딩 모델 추론은 기본 조사 흐름의 범위에 포함하지 않습니다.
